# GUI 参数工作台开发计划

## 目标

将现有固定参数表扩展为可搜索、可筛选、可校验的参数工作台。尽可能覆盖当前模型和计算中真正有效的参数，同时避免展示失效字段、派生量、兼容字段和内部求解状态。

## 参数纳入条件

参数必须同时满足：

1. 当前生产代码实际读取；
2. 修改后能够影响现有模型或计算结果；
3. 具有稳定的物理或数值意义；
4. 具有明确单位；
5. 可以独立、安全地编辑和校验；
6. 可以用面向用户的中文说明。

## 明确排除

- 已弃用兼容字段；
- 当前生产路径不读取的占位字段；
- 由其他参数自动计算的派生量；
- 对称矩阵中的重复元素；
- 内部迭代初值和临时状态；
- 字符串元数据；
- 无法说明实际作用或无法安全校验的字段。

## 页面设计

参数页计划提供：

- 参数类别筛选；
- 关键词搜索；
- 常用、全部和高级视图；
- 仅显示已修改参数；
- 参数名称、当前值、单位、允许范围、参数依据和说明；
- 恢复选中参数、当前类别或全部参数；
- 角度以度显示，内部仍使用弧度；
- 修改成功后使旧配平、线性化和响应结果失效。

界面只使用面向用户的中文。界面不显示源代码字段路径、开发阶段名称、测试术语、Git术语、内部原因代码或开发者分类标签。

## 架构

建立独立的参数目录服务，统一保存：

- 参数元数据；
- 读取与写入映射；
- 显示单位转换；
- 允许范围；
- 参数依赖；
- 校验规则；
- 常用或高级分组。

GUI回调只调用服务，不复制模型公式，也不在界面文件中维护大型读写分支。

## 开发阶段

### 阶段1：只读参数审计

扫描 `params_nominal.m` 中的全部数值字段，并追踪它们在 `model/`、`analysis/` 和 `services/` 中的实际使用。输出完整纳入与排除清单，不修改生产代码。

### 阶段2：参数目录与校验服务

建立统一参数目录、读写服务和扩展校验。

### 阶段3：GUI页面

实现搜索、筛选、编辑、说明、恢复和修改标记。

### 阶段4：验证与收尾

完成参数目录测试、GUI文本测试、服务回归、人工界面检查，并只运行一次完整回归。

## 关键校验

至少覆盖：

- 旋翼半径和桨叶质量变化后派生量同步更新；
- 惯量矩阵对称且正定；
- 惯量变化率在0至90度范围内保持有效；
- 操纵上下限顺序正确；
- 网格数量保持整数；
- 角度显示与内部弧度转换正确；
- 向量和矩阵分量编辑不影响其他分量；
- 线性化状态与操纵差分步长可以逐通道编辑。

本任务不修改名义参数文件、模型方程、配平算法、线性化算法或响应算法。
